# Примеры клиентов

Клиенты только на стандартных библиотеках — ничего устанавливать не
нужно. Каждый показывает один и тот же набор навыков работы с HTTP API:

1. Загрузка файла `multipart/form-data` на `POST /v1/audio/transcriptions`.
2. **Ретраи на 429**: чтение `Retry-After` + экспоненциальный запас,
   максимум 5 попыток.
3. **Отказ ретраить 500**: серверная ошибка повтором не лечится —
   отличие 429 от 500 в том и состоит.
4. **Таймаут** на весь запрос: зависший сервер не подвешивает клиента.
5. **Валидация тела ответа**: даже при 200 JSON может быть битым.
6. **X-Request-Id**: клиент кладёт свой id, сервер возвращает его в
   ответе и пишет в лог — корреляция «запрос ↔ лог».

| Файл | Запуск | Требует |
|---|---|---|
| [transcribe.py](transcribe.py) | `python3 transcribe.py http://127.0.0.1:8080 lecture.mp4 ru` | Python 3 |
| [transcribe.js](transcribe.js) | `node transcribe.js http://127.0.0.1:8080 lecture.mp4 ru` | Node 18+ (fetch, Blob, FormData) |
| [transcribe.go](transcribe.go) | `go run transcribe.go http://127.0.0.1:8080 lecture.mp4 ru` | Go |

## Сервер-тренажёр

Каждый навык отрабатывается на своём режиме сервера — по одному за раз:

```bash
# Ретраи: первые два запроса отбиваются 429, третий проходит.
# Клиент должен дождаться и получить результат, а не сдаться.
./serve.sh -emulate-429 first:2 -retry-after 2

# Серверные ошибки: повтор бессмыслен, клиент должен сообщить об ошибке сразу.
./serve.sh -emulate-500 always

# Таймауты: пяти секунд хватает, чтобы таймаут в одну секунду
# сработал, а в тридцать — нет.
./serve.sh -slow 5

# Валидация: 200 с обрезанным JSON — клиент обязан это поймать.
./serve.sh -emulate-broken-json always
```

Запустите режим, затем любой из клиентов:

```bash
python3 transcribe.py http://127.0.0.1:8080 lecture.mp4 ru
```

`/health` и `/v1/models` под имитацию не попадают — по ним удобно
проверять, что сервер жив. Спецификация всего API: `GET /v1/openapi.json`
(открывается в Swagger UI через editor.swagger.io).
